# 后台管理双菜单功能手动改造说明

> 本文档用于手动改造代码。当前代码已按你的要求还原，不再保留我自动写入的实现。下面记录需要你手动修改的文件、建议改法和注意点。

## 1. 改造目标

实现后台管理两套菜单：

- 公司管理菜单：`MenuStatus.CompanyManagement = 1`
- 用户管理菜单 / 个人中心菜单：`MenuStatus.CompanyPerson = 2`

需要满足：

1. 登录后默认进入用户管理菜单，并动态跳转用户菜单接口返回的默认菜单。
2. 用户可在公司管理菜单与用户管理菜单之间切换。
3. F5 刷新后保持当前菜单模式。
4. 菜单切换不重置布局模式。
5. 默认高亮当前菜单项。
6. 前端不能写死 `menuCode`，`menuCode` 必须来自接口返回的菜单节点。

## 4. 菜单公共 helper

文件：`packages/platform/admin-vue/src/composables/use-menu/helper.ts`

### 4.1 `formatUrl` 必须从节点动态取值

不要写死：

```ts
'/user-homepage?menuCode=user-homepage&navigationType=2'
```

应该从接口节点生成：

```ts
const formatUrl = (node: MenuTreeOptions): MenuTreeOptions => {
  if (!node.url) return node;

  const url = new URL(node.url, window.location.origin);
  url.searchParams.set('menuCode', node.menuCode);
  url.searchParams.set('navigationType', String(node.navigationType));

  node.url = `${url.pathname}${url.search}`;
  return node;
};
```

好处：

- `menuCode` 来自接口。
- 避免重复追加 query。
- 后端以后调整 `menuCode`，前端不用改。

### 4.2 保留默认菜单查找

```ts
const findFirstAvailableMenu = (menus: MenuTreeOptions[]): MenuTreeOptions | undefined => {
  for (const menu of menus) {
    if (menu.url) return menu;

    const child = findFirstAvailableMenu(menu.children || []);
    if (child) return child;
  }
};
```

这用于：

- 登录后进入用户菜单默认页。
- 切换菜单后进入目标菜单默认页。

### 4.3 URL 匹配建议支持 path 匹配

因为刷新或手动访问时 URL query 可能不完整，建议 `findMenuByUrl` 支持：

- 完整 `fullPath` 匹配。
- path 相同兜底匹配。

示例：

```ts
const parseUrl = (url?: string) => {
  if (!url) return;
  return new URL(url, window.location.origin);
};

const isSameMenuUrl = (menuUrl?: string, targetUrl?: string) => {
  const parsedMenuUrl = parseUrl(menuUrl);
  const parsedTargetUrl = parseUrl(targetUrl);

  if (!parsedMenuUrl || !parsedTargetUrl) return false;

  const menuFullPath = `${parsedMenuUrl.pathname}${parsedMenuUrl.search}`;
  const targetFullPath = `${parsedTargetUrl.pathname}${parsedTargetUrl.search}`;
  if (menuFullPath === targetFullPath) return true;

  return parsedMenuUrl.pathname === parsedTargetUrl.pathname;
};
```

## 5. 菜单初始化与切换

文件：`packages/platform/admin-vue/src/composables/use-menu/use-menu.ts`

核心原则：

```text
确定 targetNavigationType
  -> queryMenuList({ navigationType: targetNavigationType })
  -> formatUrl 菜单树
  -> 找 defaultMenu
  -> 必要时 router.push(defaultMenu.url)
```

### 5.1 初始化时解析菜单模式

初始化菜单模式优先级：

```text
route.query.navigationType
  > store.state.navigationType
  > MenuStatus.CompanyPerson
```

### 5.2 切换菜单时请求目标菜单

切换时要注意：接口参数必须用目标类型，而不是旧类型。

```ts
const targetNavigationType = isChangeNavigation
  ? getOppositeNavigationType(systemModuleAccess.state.navigationType)
  : resolveNavigationType();

const { data } = await queryMenuList({ navigationType: targetNavigationType });
```

### 5.3 登录进入 `/` 后动态跳转

不要在登录页或 guard 里写死首页。

建议登录后只进入：

```ts
router.push({
  path: '/',
  query: {
    navigationType: String(MenuStatus.CompanyPerson),
  },
});
```

然后在 `useMenu` 初始化里：

```ts
if (route.path === '/' && defaultMenu) {
  await router.replace(defaultMenu.url);
}
```

### 5.4 切换菜单后动态跳目标默认菜单

```ts
if (isChangeNavigation && defaultMenu) {
  const homeTab = createTabByMenu(defaultMenu);
  systemModuleAccess.setTabBarList([homeTab], targetNavigationType);
  systemModuleAccess.setActiveTab(homeTab.fullPath);
  await router.push(defaultMenu.url);
  return;
}
```

如果暂时不做 store 分组，`setTabBarList` 可以先不传第二个参数。

## 6. Store 建议改造

文件：

- `packages/platform/admin-vue/src/stores/modules/system-module-access/index.type.ts`
- `packages/platform/admin-vue/src/stores/modules/system-module-access/index.ts`

### 6.1 最小改造

如果只想先满足菜单切换和刷新：

- 保留当前平铺结构。
- 确保持久化包含：

```ts
'state.activeTabFullPath'
'state.tabBarList'
'state.menuList'
'state.cachedViewNames'
'state.navigationType'
```

当前代码已经具备这部分。

### 6.2 完整改造：按菜单模式分组

如果要让公司管理和用户管理的 tabs/cache 独立保存，增加：

```ts
export type SystemNavigationOptions = {
  tabBarList: TabBarListOptions[];
  menuList: MenuTreeOptions[];
  cachedViewNames: string[];
};

export type SystemModuleAccessState = {
  activeTabFullPath: string;
  navigationType: MenuStatus;
  tabBarList: TabBarListOptions[];
  menuList: MenuTreeOptions[];
  cachedViewNames: string[];
  navigationState: Record<MenuStatus, SystemNavigationOptions>;
  routeRecordRaw: RouteRecordRaw[];
};
```

同时增加 actions：

- `getNavigationState(navigationType?)`
- `setNavigationType(navigationType)`
- `setMenuList(menuList, navigationType?)`
- `setTabBarList(tabBarList, navigationType?)`
- `addTab(tab)`
- `removeTab(fullPath, navigationType?)`
- `addCachedView(name, navigationType?)`
- `removeCachedView(name, navigationType?)`
- `clearCachedViews(navigationType?)`

注意：如果使用组合式 Pinia，并且返回对象类型太复杂，`vue-tsc` 可能报：

```text
The inferred type of 'systemModuleAccessStore' cannot be named...
```

解决方式：给 store 返回值声明显式类型。

## 8. Tab 同步

文件：`packages/platform/admin-vue/src/composables/use-tab-bar-route-sync/use-tab-bar-route-sync.ts`

当前风险：

- 代码里读取了 `systemModuleAccess.state.menulist`，但 store 字段是 `menuList`。
- 调用了 `addTab/addCachedView`，当前 store 里没有这些 action。

手动改造时有两种选择。

### 方案 A：先不启用 Tab 同步

保持 `guard.ts` 中：

```ts
// syncRouteToTab(to);
```

这样工作量小，只实现菜单切换和高亮。

### 方案 B：启用 Tab 同步

需要同时实现 store actions，并将菜单查找改为：

```ts
const navigationType = Number(route.query.navigationType || systemModuleAccess.state.navigationType) as MenuStatus;
const menuCode = String(route.query.menuCode || '');
const menu = findMenuByCode(systemModuleAccess.getNavigationState(navigationType).menuList, menuCode);
```

并且在同步前加保护：

```ts
if (route.path === '/' || !route.query.navigationType || !route.query.menuCode) return;
```

const cachedViewNames = computed(() => systemModuleAccess.state.cachedViewNames);

## 15. 手动改造建议顺序

建议你按这个顺序来，方便每一步验证：

1. 只改 `helper.ts` 和 `use-menu.ts`，先实现动态默认菜单跳转。
2. 改 `guard.ts` 或 `login.vue`，让登录后进入 `/` + `navigationType=2`。
3. 验证登录后能动态跳用户菜单默认页。
4. 验证点击切换菜单能动态跳目标菜单默认页。
5. 验证 F5 后 `route.query.navigationType` 能恢复菜单模式。
6. 再决定是否做 Store 分组、Tab 同步、KeepAlive。
7. 最后跑 build。
